# Safe Config Change

Подготовь безопасный план изменения JSON-конфигурации и покажи только отредактированный результат.

## Критические ограничения

- Соблюдай правило `rules/local-config-guard.md`.
- Не выводи исходные секреты и не составляй diff вне `structural_diff`.
- Не записывай файлы и не применяй изменение без отдельного явного подтверждения.

## Входные данные

- Исходный JSON как текст.
- Требуемое изменение.
- Итоговый JSON как текст, если пользователь уже подготовил его.

## Алгоритм

1. Передай исходный JSON в `validate_json`.
2. Если проверка не пройдена, остановись и верни безопасную ошибку без фрагментов входа.
3. Передай исходный JSON в `redact_secrets`; используй результат только для объяснения контекста.
4. Если итоговый JSON не дан, подготовь изменение в памяти, сохраняя типы и структуру полей; не копируй секреты в ответ.
5. Передай итоговый JSON в `validate_json`. Если проверка не пройдена, остановись безопасно.
6. Передай исходный и итоговый JSON в `structural_diff`.
7. Проверь, что diff содержит только пути и виды изменений, затем сформируй отчёт.

## Формат вывода

Верни:

- статус валидации исходной и итоговой конфигураций;
- краткое описание изменения;
- structural diff из MCP без значений;
- отредактированный итоговый JSON только если пользователь просил его показать;
- отметку, что изменение не применялось.

## Приёмочный чек-лист

- [ ] Оба JSON прошли `validate_json`.
- [ ] Любой показанный JSON получен через `redact_secrets`.
- [ ] Diff получен через `structural_diff` и не содержит значений.
- [ ] Секреты и исходные ошибки парсера не раскрыты.
- [ ] Файлы и команды не изменялись без подтверждения.
