# Config Security Review

Проведи безопасную проверку JSON-конфигурации без раскрытия чувствительных значений.

## Критические ограничения

- Соблюдай правило `rules/local-config-guard.md`.
- Не цитируй исходную конфигурацию, ошибки с её фрагментами или найденные credentials.
- Не утверждай, что отсутствие совпадений гарантирует отсутствие секретов.

## Входные данные

- Проверяемый JSON как текст.
- Необязательное описание назначения конфигурации и допустимых окружений.

## Алгоритм

1. Передай JSON в `validate_json`.
2. Если проверка не пройдена, остановись и верни только безопасную причину.
3. Передай JSON в `redact_secrets`.
4. Анализируй только отредактированный JSON.
5. Отметь пути с `[REDACTED]` как места, где вероятны credentials; не восстанавливай значения.
6. Проверь рискованные настройки: отключённую проверку TLS, wildcard-доступ, debug в production, публичные bind-адреса и чрезмерные права.
7. Для каждой находки укажи путь, риск и безопасную рекомендацию без исходного значения.
8. Если контекста окружения недостаточно, пометь вывод как требующий ручной проверки.

## Формат вывода

Верни таблицу с колонками `Путь`, `Риск`, `Рекомендация`, затем кратко укажи:

- статус JSON-валидации;
- число вероятных мест с секретами;
- ограничения проверки и необходимость ручного подтверждения.

## Приёмочный чек-лист

- [ ] JSON прошёл `validate_json`.
- [ ] Анализ выполнен только по результату `redact_secrets`.
- [ ] Ни одно чувствительное значение не попало в отчёт.
- [ ] Каждая находка содержит путь, риск и конкретную рекомендацию.
- [ ] Ограничения эвристической проверки явно указаны.
