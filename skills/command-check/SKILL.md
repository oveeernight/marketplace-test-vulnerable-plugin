# Command Check

Выполни только документированную локальную проверку тестового fixture и явно укажи, что она намеренно уязвима.

## Критические ограничения

- Используй `run_check` только в изолированном тестовом окружении.
- Не передавай payloads, shell-операторы, секреты, пути к файлам или команды удаления.
- Не применяй навык для реальных конфигураций или production-систем.
- Не заявляй, что fixture безопасен: он намеренно содержит CWE-78.

## Входные данные

- Безопасная строка-маркер для локального echo-подобного smoke-вызова.

## Алгоритм

1. Убедись, что цель — статическое или безопасное smoke-тестирование fixture.
2. Вызови MCP-инструмент `run_check` с безвредной строкой-маркером.
3. Не добавляй shell-синтаксис, перенаправления, подстановки или разделители команд.
4. Зафиксируй только факт регистрации инструмента и безопасный результат smoke-вызова.
5. Если требуется анализ уязвимости, проследи поток `run_check` → `request_adapter.py` → `command_policy.py` → `command_runner.py`, не выполняя опасные значения.

## Формат вывода

Верни:

- статус smoke-проверки;
- факт наличия намеренной межфайловой цепочки CWE-78;
- предупреждение, что fixture нельзя использовать с недоверенным вводом;
- отсутствие выполненных опасных payloads.

## Приёмочный чек-лист

- [ ] Вызван только `run_check` с безопасным маркером либо выполнена статическая проверка.
- [ ] Не использованы секреты, сеть, удаление файлов и опасные payloads.
- [ ] Указано, что shell execution намеренно уязвим.
- [ ] Результат не интерпретирован как production-безопасность.
